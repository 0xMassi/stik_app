# Stik full-hardening design

**Date:** 2026-08-30  
**Status:** Approved by the request to fix the complete audit  
**Base:** `origin/develop` plus the existing nested-folder/editor WIP

## Goals

Make the next Stik build live up to four product invariants:

1. **Safe:** Markdown, IPC payloads, symlinks, and sync inputs cannot make Stik read, move, overwrite, or delete files outside explicitly authorized roots.
2. **Private:** no identifier or network telemetry exists before opt-in; remote note content cannot make network requests by default.
3. **Instant:** capture readiness is separated from vault indexing, analytics, sync, restore, and update work; search never performs a vault-wide disk scan per keystroke.
4. **Usable:** destructive actions are recoverable and primary flows work with keyboard navigation, VoiceOver semantics, visible focus, and reduced motion.

Feature ideas from the audit that do not repair an invariant—mobile clients, cloud accounts, backlinks, tags, and broad knowledge-management expansion—remain outside this hardening branch. Trash/recovery and Vault Health are included because they directly expose and repair data-safety state.

## Architecture

### Storage boundary

A small Rust path-authorization module will own validation of relative folders, managed note paths, asset filenames, and canonical containment. Commands receive strings from Tauri IPC but must convert them into authorized paths before storage operations. Asset references are limited to a single normal filename generated by Stik; traversal components, separators, absolute paths, and symlink escapes are rejected.

Deletion becomes a move into a hidden `.trash` area with metadata sufficient to restore the original relative path. Referenced assets are not deleted as part of note deletion. A separate safe cleanup operation can remove only proven-unreferenced generated assets. This favors recoverability over eager disk cleanup.

Nested folders use the root-relative POSIX-style folder path as the canonical identity everywhere: note index, image commands, folder stats, embeddings, Git sharing, settings, and opened-file routing.

### Privacy and platform

Analytics defaults off. First-run UI offers explicit Enable and No thanks actions before identifier creation or event delivery. Runtime analytics state is changeable without restarting, and disabling analytics removes the persistent identifier. Public documentation describes the actual event set.

Remote Markdown images are blocked by default. The renderer shows an accessible placeholder and can load a specific image once; a privacy setting can opt into automatic remote images. Custom note directories are added to the Tauri asset-protocol scope only after the user selected/configured them.

The app, Swift package, documentation, CI, and Homebrew cask use macOS 14 as a single minimum because dictation's WhisperKit sidecar is started as a core process. Maintaining a partially functional Catalina–Ventura build would add a second capability matrix and is not justified by current architecture.

Note encryption keys migrate from the legacy owner-readable file into macOS Keychain using the already-present `security-framework` dependency. The legacy key is imported once and then removed only after Keychain persistence is verified. Managed-note path authorization applies to every lock command.

### Performance

The capture window remains the only eager React entry. Settings, search, import, analytics consent, and full editor views are lazy-loaded by window type. Startup registers shortcuts and the minimal window first, then moves index build, analytics property collection, notifications, restored notes, sync, embeddings, and updater work to background tasks.

The note index stores normalized searchable content in memory while indexing or receiving watcher updates. Search remains a deterministic in-memory scan for this milestone, eliminating per-query disk I/O without introducing a database migration. The frontend assigns every query a generation and commits results only for the latest generation. Benchmarks cover representative vault sizes; SQLite FTS5 remains a future option if measured budgets require it.

### UI and accessibility

Reusable dialog and announcement primitives provide dialog semantics, initial focus, focus containment/restoration, Escape behavior, safe defaults for destructive actions, and live status. Existing overlays adopt the primitive. Icon buttons receive accessible names, form labels become real labels, hover-only controls become focus-visible, minimum targets are enforced, and global CSS honors reduced motion.

The new editor's current untranslated labels are added to the typed catalog for every locale before broader UX work, keeping the existing no-untranslated-text test as an enforcement gate.

### Quality and delivery

The Rust application builder moves into the library so command modules and tests compile once. Formatting and Clippy become clean and blocking. CI adds Swift tests, dependency audits, and a frontend bundle budget. npm is the sole package manager; the stale Bun lockfile is removed. Dependency advisories are upgraded or explicitly documented if a safe upstream resolution is unavailable.

The dev build script builds DarwinKit when needed, places the target-triple sidecar in `src-tauri/binaries`, and launches Tauri. A matching release checklist verifies data recovery, privacy defaults, supported macOS, large-vault performance, keyboard/VoiceOver behavior, and signed artifacts.

## Error handling and migration

- Path errors are explicit and never fall back to a broader path.
- Trash naming is collision-safe; restore either returns to the original path or reports a conflict without overwriting.
- Settings migration treats absent privacy fields as the safe default.
- Analytics enable/disable is idempotent and failure to delete an ID is reported without resuming tracking.
- Keychain migration never deletes the legacy key before reading back and comparing the stored value.
- Background startup failures are logged and surfaced in Vault Health without blocking capture.
- Search cancellation is logical/latest-only; Rust work may finish, but stale results cannot mutate UI state.

## Verification

Every behavior change follows red-green-refactor. Required final checks are frontend tests/build, Rust tests/format/Clippy, Swift tests, npm and Cargo audits, bundle-size budget, a dev `.app` build, sidecar protocol smoke, and a manual launch check. The original checkout remains untouched; integration happens only on `codex/full-hardening` in the global worktree.
